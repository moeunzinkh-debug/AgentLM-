# AgentLM — real agent mode

Everything in this build is generated by a real model or fetched from a real server.
There is no scripted/canned reply path left in the app: if nothing can answer, the chat
shows the actual error plus how to fix it instead of text that was written at build time.

## 1. Where answers come from

`Settings → Engine & Keys` picks the source of truth:

| Engine | Transport | Notes |
| --- | --- | --- |
| Google Gemini | `streamGenerateContent?alt=sse` | Needs an API key (Settings, or `GEMINI_API_KEY` at build time). Tokens are read live, not replayed. |
| Ollama / llama.cpp / LM Studio / vLLM / OpenRouter / Groq / HF router | OpenAI-compatible `/chat/completions` SSE | Any server that speaks `choices[].delta.content`. |
| On-device LiteRT-LM | Google AI Edge runtime, local weights | Opt-in build (see §4). Runs the file you downloaded in Model Hub. |

Fallback order is `selected engine → on-device (if weights + runtime exist) → other ready
engines`, and it only switches **before** the first token, so a reply is never spliced.

Pointing at a LAN server:

```bash
# llama.cpp
llama-server -m qwen2.5-0.5b-instruct-q4_k_m.gguf --host 0.0.0.0 --port 8080 -c 4096
# ollama
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

Then in Settings use `http://<computer-ip>:8080/v1` (or `:11434/v1`) and press **Test
connection**. `localhost` never works from a phone — it points at the phone itself.

## 2. Real model downloads

`ModelDownloadManager` + `HfRepositoryClient` do the actual work:

* the repo tree is queried (`/api/models/{id}/tree/main?recursive=true`) so the sizes shown in
  the hub are the real weight-file bytes, not a guess from the parameter count;
* the file chosen is the **largest quantization that still fits the RAM budget measured on this
  device** (`ResponseBudgetAdvisor.pickFor`), preferring the quantization tag in Settings;
* transfer writes to `<name>.part`, resumes with `Range: bytes=N-` when the CDN supports it,
  reports real MB/s + ETA, and checks `StatFs` free space before starting;
* `manifest.json` next to the weights is reconciled at app start, so a process kill mid-download
  shows "paused, N % kept" instead of a phantom state;
* progress is emitted on a 180 ms budget, not per 64 KB read.

## 3. Why it no longer freezes while a reply streams

Findings taken from the release notes/issues of
[`orailnoor/cross-platform-llm-client` (PrivateLM)](https://github.com/orailnoor/cross-platform-llm-client/releases)
and how each is implemented here:

| Problem they fixed | Implementation in AgentLM |
| --- | --- |
| "Fixed empty responses on Pixel 6/7/8 by running Gemma models in single-threaded mode" | `ResponseBudgetAdvisor.advise()` pins threads to 1 for Tensor + Gemma-family weights and shows why in Settings → GPU / CPU. |
| "automatic garbage-token filtering" | `ResponseStreamer.sanitize()` drops control chars, surrogate fragments, whitespace bursts and leaked chat-template markers **before** they can trigger a repaint. |
| "LiteRT loading now retries on CPU when GPU initialization fails" (#11) | `NativeLlmEngine.ensureSession()` retries with `backend = "cpu"` when a GPU delegate load throws; `policy.fallbackGpuToCpu` toggles it. |
| Mid-stream UI corruption ("message leaking when switching chats", #17-class) | `ChatViewModel.generationSerial` — a superseded generation can never commit into a newer chat; `MessageItem` keys are stable ids. |
| "Downloads are persisted and reconciled after leaving or restarting the app" (#24) | `manifest.json` + `ModelDownloadManager.reconcile()`. |
| "Device Compatibility Advisor … recommends the most suitable quantization format" | Settings → Response Tuning verdict card (OPTIMAL / TIGHT / OVER BUDGET) + quantization picker; Model Hub lists per-model fit from measured RAM. |
| Frozen/hung generation | `ResponseStreamer` applies three bounded waits — prefill timeout, inter-token idle timeout, hard wall-clock cap — and always commits the partial text. |
| Streaming updates janky | Deltas are **coalesced**: at most one snapshot per `flushIntervalMs` (and only after `minFlushChars`). The message list is written twice per turn (open + commit), never per token, so the `LazyColumn` item count is stable while typing. |
| Scroll fighting the stream | `ChatScreen` follows only while `derivedStateOf` says the list is near the bottom, jumps with `scrollToItem()` during streaming (no animation restarts), and detaches as soon as the user scrolls up. |
| Markdown re-parse cost | While tokens arrive, the bubble renders plain text; full Markdown parsing runs once at commit. Completed bubbles are memoised by `MarkdownParseCache`. |
| OOM/thrash on low-RAM devices | `maxOutputTokens` and the prompt budget are clamped from measured free RAM and the model's KV-cache growth; attachment bodies are truncated to the context window (`PromptBudget.clampBody`). |

## 4. On-device execution (the default)

`agentlm.nativeEngine=true` is set in `gradle.properties`, so a normal build already contains the
runtime that executes the downloaded weights on the phone. Opt out for a slim, server-only APK:

```bash
gradle assembleDebug -Pagentlm.nativeEngine=false
```

The enabled variant adds `com.google.ai.edge.litertlm:litertlm-android:0.12.0` (same pin as the
reference client, which also uses Java 17 + minSdk 24), compiles
`app/src/litertlm/java/.../LiteRtLmBackend.kt` (Engine → Conversation →
`sendMessageAsync(Contents)` Flow → per-chunk `onDelta`) and aligns the module on JVM 17.
`NativeBackends` finds it reflectively; Settings shows the runtime as READY, and Model Hub's
"Use offline" then switches the active engine to the local one. Without the flag the app keeps
working through remote engines and says so plainly.

For the GPU delegate the manifest already declares `libOpenCL.so` / `libvndksupport.so`.

## 5. Sampling ownership

`ResponsePolicy.temperature/topP/topK` use a negative value to mean "follow the persona", so
`Personas` stays authoritative until the user deliberately overrides a slider in
`Settings → Response Tuning`. The resolved numbers are attached to every `EngineRequest` and
forwarded per request — Gemini `generationConfig.topK`, OpenAI-compatible `top_k` (only when it
differs from 40, to stay compatible with strict endpoints) and LiteRT-LM `SamplerConfig`.
